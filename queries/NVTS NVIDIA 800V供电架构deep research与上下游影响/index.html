    NVTS NVIDIA 800V供电架构deep research与上下游影响¶

    Authority boundary（2026-07-14）：本页不是主registry选中的current action SOT，只保留proof/evidence、research checkpoint或dated provenance。正文任何 Buy/Hold/Sell、action、price band、仓位、no-chase/trim 或 hline 文字均为historical reference，不得据此执行或维护。Current action只由科技主线研究ticker统一台账的selected SOT承担；对应row为none时即无current wiki action。

    更新时间：2026-06-24 CEST 关联导航：NVTS — Navitas · NVDA — NVIDIA · AI 互连、光网络与 DCI · 机房电气、rack power、散热与交付 · 供电与电气基础设施 follow-up tracking台账

    先回答¶

    最近这条不是严格意义上的“NVTS 与 NVIDIA 签了 800V 供电采购协议”。更准确写法：NVIDIA 把 800 VDC 作为下一代 AI factory / Kyber / MGX power architecture 方向，Navitas 被 NVIDIA 官方列入 800 VDC electrical ecosystem / silicon partner，并且 Navitas 官方披露正在与 NVIDIA / MGX ecosystem 围绕 800 VDC 与 800V-to-6V PDB 协作展示。

    所以证据强度排序是： 1. architecture proof：强。NVIDIA official technical blog 已把 800 VDC 作为 2027 起 1MW rack 及以后架构方向。 2. ecosystem / named partner proof：强于普通产品新闻。NVIDIA list 中出现 Navitas，Navitas 也披露参与 NVIDIA Partner Ceremony / MGX Ecosystem Showcase。 3. commercial proof：仍未闭合。当前 sources 没有 purchase commitment、exclusive supply、revenue dollars、volume production award、NVIDIA 或 hyperscaler named deployment。

    背后含义¶

    800V 的核心不是“电压数字好看”，而是 AI rack 从几十 / 一两百 kW 走向 1MW+ 后，旧 54V rack power / 多级 AC-DC-DC 转换开始撞上三件事： - 铜和空间：低压高电流需要更粗 busbar / cable，rack 内空间被 power shelf 挤占；NVIDIA 写到 1MW rack 用 54V 会出现巨大铜和 U 位压力。 - 效率和故障点：多级转换带来能耗、热和 PSU / fan 维护点；NVIDIA 给出的目标是 end-to-end efficiency up to 5%、maintenance cost up to 70% 降低、TCO up to 30% 改善。 - 架构统一：把 AC-to-DC 更集中到 facility / perimeter，再用 800 VDC busway 直送 IT rack，rack / board 侧再做高效率 DC-DC step-down。GPU 不是孤立升级，供电架构要跟着变。

    对 NVTS 的含义：它从“GaN/SiC 可能适合数据中心电源”的松散叙事，升级成 NVIDIA 800V ecosystem named option。这会提高它作为 high-beta architecture option 的可信度；但它仍然是 option，不是已规模化收入票。

    上游 / 下游传导¶

    上游 / 直接技术层¶

    • power semiconductors：GaN / SiC / controllers / protection / sensing 受益最直接。NVTS 在这里；同类 ecosystem 还包括 Infineon、TI、ADI、MPS、onsemi、ROHM、ST、Renesas 等，但当前 wiki 只把 NVTS / VICR / AEIS / BELFB 放在 power-component 观察层。
    • SST / rectifier / HVDC conversion：800 VDC 从 utility / facility 侧切入，利好中高压 SiC、industrial rectifier、solid-state transformer、protection / breaker 生态；这更靠近 GEV / ETN / HUBB / VRT / Schneider / Delta 等电气平台和系统层，不应全部归功给 NVTS。

    中游 / rack 与 board power¶

    • 800V-to-54V/50V：传统中间 bus route，Navitas 10kW 800V-to-50V platform 已有官方材料。
    • 800V-to-6V/12V：更激进，Navitas 在 GTC / MGX showcase 展示的 PDB 试图跳过 48V / 50V intermediate bus converter，直接贴近 GPU board。若这条路线成为主流，NVTS 弹性更大；若行业继续保留中间 bus，收益会更分散。

    下游 / 机房与系统落地¶

    • rack-scale compute：NVIDIA Kyber / MGX / Rubin Ultra 这类更高功率密度平台，是需求牵引源。
    • power rooms / busways / switchgear / cooling：800V 不是只在 board 上发生；它会把更多价值推给 facility electrical / power management / thermal layer。Wiki 里已经 cover：机房电气、rack power、散热与交付、供电与电气基础设施 follow-up tracking台账、GEV / HUBB / ETN / PWR / VRT / NVT 等。
    • manufacturing / system integration：如果 rack architecture 变化，服务器 / rack 集成商要重做 power shelf、tray、busway、thermal envelope；这对 DELL / CLS / FN 这类系统交付层是间接 read-through，但不能写成 NVTS 客户链。

    我们 Wiki 现有 cover 情况¶

    已有 cover： - NVTS — Navitas：已把 NVTS 归到 conditional / power-architecture option，并记录 Great Wall 400V、10kW 800V-to-50V、Ruby PSU、NVIDIA GTC 800V-to-6V PDB、SST/800V DC demo。 - AI 互连、光网络与 DCI：已有 板级 / 机架供电器件 小层，列 NVTS / AEIS / VICR / BELFB，并明确不要和 optics / networking 混在一起。 - 供电与电气基础设施 follow-up tracking台账：已有 power provider、电气设备、EPC、储能桥接、功率器件的横向 tracking；本次应把 NVTS 的 proof gap 从普通 400V/800V platform 升到 NVIDIA 800V ecosystem / no commercial attribution yet。 - 机房电气、rack power、散热与交付：覆盖 facility electrical / rack power / thermal / EPC，但它更多是落地层，不是 NVTS 单名 thesis 页。

    缺口：还没有一个专门解释 NVIDIA 800 VDC architecture -> power semis -> rack/facility/electrical downstream 的单页。本页补这个缺口。

    动作结论¶

    NVTS：conditional / reduce-no-chase / no new position 不变。

    原因：NVIDIA 800V named ecosystem 明显提高 thesis 质量，但 2026-06-05 market snapshot 显示 NVTS intraday USD 25.38、P/S 约 126，且公司 Q1 revenue 仍只有 USD 8.6M、GAAP gross margin -9.3%、net loss USD 33.8M，另有 ATM / earnout 稀释 overhang。这里更像“架构证据变硬，但价格和商业兑现没给安全垫”。

    后续 proof gates¶

    升级条件： - NVIDIA / hyperscaler / PSU / rack OEM 出现明确 design win、volume qualification、或 revenue/backlog attribution。 - 800V-to-6V / 800V-to-12V direct conversion 路线进入量产设计，而不只是展台 / reference platform。 - high-power / data-center revenue 单独量化，毛利从负转正并证明不是低质量抢市场。 - 价格回到 source-backed reset 区间后，证据仍继续变硬。

    降级条件： - NVIDIA ecosystem language 长期不转商业订单。 - 800V 架构推进慢于 2027 / Kyber 节奏，或行业采用更偏传统中间 bus 的供应链路线。 - 融资 / earnout / cash burn 扩大，早期 option 被迫高成本融资。

    TradingView / HERMES：本页不触发新 chart mutation；NVTS 已有 2026-06-05 source-backed lines 18.20 / 23.60 / 29.50 / 34.17，除非重新做 market snapshot，不新增 hlines。

    2026-06-24 latest evidence addendum¶

    NVTS 本轮不升级，原因不是 800V thesis 破坏，而是融资/兑现风险变得更硬： - 2026-06 S-3/ATM 把可售 Class A common stock 上限抬到 USD 500M，明显高于此前观察到的 smaller ATM framing。 - 2026-06-15 8-K 后，earnout 已从部分触发推进到基本完全触发/发行：aggregate 9.841948M shares issued，all Triggering Events met。 - Q1 10-Q 显示 Distributor A = 59% of revenue，Hong Kong = 76%；Q1 revenue USD 8.6M 对 USD 4.7B market cap 仍极小。 - 2026-06-24 Yahoo readback last about USD 18.60、日内约 -15.8%，接近旧 HERMES 18.20 reset line；这只是 first support / proof-check，不是自动 add。当天没有查到新的 issuer-primary operating break，selloff 更像高 beta unwind + dilution-risk repricing。

    结论：保留 conditional / no new position，除非后续出现 NVIDIA / PSU / hyperscaler / rack OEM 的 purchase commitment、volume qualification 或 revenue/backlog attribution，同时 ATM 使用和 gross margin 证明不恶化。

    2026-06-05 peer restudy 补全¶

    并行复核后，相关名字不应按“都受益于 800V”混成一篮子： - VICR：需要中性边界更新。800V -> 6V/12V 直降路径削弱“48V/50V 必经”的默认假设；但 Vicor 仍有 800/400VDC -> 54/50/48V 与近端 current-multiplier 分支，不能写成 thesis break。 - AEIS / BELFB：需要 map hygiene。AEIS 更偏 rack-entry front-end PSU / ORv3/HPR power shelf；BELFB 是更二阶的 OCP/open-rack PSU、power shelf/rack、magnetics/connectivity 组合；两者都不是 NVIDIA 800V commercial attribution。 - POWL / HPS.A：facility electrical-delivery 线被 800V 架构进一步确认。POWL 的 USD 400M+ post-Q2 mega data-center order 让其 commercial proof 强于 NVTS 当前收入归因；HPS.A 则是 slower-burn transformer / power-quality read-through，Q1 2026 data-centre activity 与 backlog 支撑真实但仍缺 named customer / DC split。 - VRT / ETN / HUBB / NVT：本轮不需要 active entity rewrite。VRT / ETN 是 NVIDIA ecosystem read-through，但仍非订单/收入；HUBB / NVT 暂只是 broad facility read-through。

    动作上，NVTS 不因 peer restudy 改线或升档；真正需要补全的是 topology map 与 follow-up gates。
