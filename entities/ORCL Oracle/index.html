    ORCL — Oracle¶

    更新时间：2026-06-02 CEST（sync hygiene；HERMES/TV hlines 已于 2026-05-29 verified，155-165 仍是 wiki-only re-underwrite） 行业页：云与算力需求方 归类：直接 / 下游锚点

    链条位置¶

    下游需求锚。Oracle 不是“卖电”或“卖互连”的公司，但它是真实扩建 AI 云和数据中心园区的买方。

    为什么它在这条链上¶

    Q3 FY2026 已把 Oracle 从普通 cloud participant 推成整条 AI/DC 链的 demand-anchor：RPO USD553B、+325% YoY；Cloud Infrastructure / IaaS revenue USD4.9B、+84%；公司维持 FY2026 capex USD50B，并把 FY2027 revenue guide 提到 USD90B。多云、数据库与新园区建设会持续拉动电力、机房、互连、散热与 storage 需求。

    我当前更愿意承认的多头逻辑¶

    订单与积压极强，OCI 仍在资本开支扩张阶段，是整条链最真实的需求背景之一。现在 ORCL 值得放进 deep-dive bucket，不是因为它是小盘弹性票，而是因为 RPO/capex/交付节奏会决定下游电力、机房、互连、散热和 storage 订单能否继续外溢。

    我当前最在意的风险¶

    资本开支很重，自由现金流和杠杆承压；USD553B RPO 需要转成真实 capacity / revenue / margin。若供电、GPU/网络交付、客户预算或融资成本放缓，链条外溢会先减速。

    一句话判断¶

    【云/下游】OCI RPO 与 IaaS 增速把它升级成 demand-anchor / capex-spillover validator；AI 受益真实，但当前位置按 rerated cloud-infra anchor 处理，不按小盘弹性票追。

    2026-05-05 deep-dive bucket note¶

    当前处理：HIGH-PRIORITY DEMAND-ANCHOR / no small-cap chase。核心问题从“OCI 有没有需求”变成三件事：RPO 转收入速度、USD50B capex 的供电/机房/互连约束、以及重融资后 FCF/杠杆能否承受。

    当前执行区间¶

    2026-05-29 状态同步：ORCL 仍是 demand-anchor / capex-spillover validator，但 enterprise-software pass 已把旧 USD 160-170 / 220-240 粗线收窄成 rerating 后的 pullback/no-chase 框架；HERMES/TV 远端 hlines 已于 2026-05-29 redsource archive root（私有研究库）readback verified，155-165 保留为 wiki-only re-underwrite gate。 - USD 155-165：re-underwrite / deeper reset；只有在 RPO 转收入、capex/FCF 和融资压力都重新核验后才提高动作。 - USD 170-178：preferred pullback / demand-anchor recheck zone；适合复核 OCI RPO 转 revenue/capacity、供电/机房交付与链条外溢。 - USD 185-205：no fresh chase / study 区；可以作为 capex-spillover validator 跟踪，不因 RPO headline 追价。 - USD 220+：trim / avoid-new-money；除非 RPO 转收入和 FCF/杠杆压力同步改善，否则先卖强或等待。
