From a role perspective, which names are anchors and which are more like ambush candidates

Anchor validators

Names that function more as demand / production / bottleneck validators:

  • MSFT Microsoft
  • AMZN Amazon
  • GOOG Alphabet
  • META Meta Platforms
  • ORCL Oracle
  • NVDA NVIDIA
  • TSM Taiwan Semiconductor Manufacturing
  • AVGO Broadcom
  • VRT Vertiv

These names are important for tracker relevance, but mainly provide:

  • validating whether the main thesis is actually strengthening;
  • giving valuation and crowding context;
  • confirming demand for smaller names.

Ambush candidates

More suitable for prioritizing small/mid/upper-mid names with repricing optionality:

  • AAOI Applied Optoelectronics
  • MTSI MACOM
  • CRDO Credo Technology
  • FN Fabrinet
  • TLN Talen Energy
  • BE Bloom Energy

Hard cases / likely false-friend pressure

Names to watch carefully because they may look like core names but lack evidence uplift or are already crowded:

  • COHR Coherent
  • OKLO Oklo
  • Some optics / power / buildout names where new orders and evidence have not increased in step after becoming too fast

Direct requirements for Trade Tracker

What not to do

  • Do not use it as a broad US market clue hunter anymore
  • Do not continue introducing finance, pharma, consumer, or other sectors as Milestone A scope
  • Do not treat megacap validation signals as ambush alpha by themselves
  • Do not assume that “semiconductors only” is the scope

What to do

First lock tracker to these three schemes:

  1. platform-ai-monetization
  2. compute-bottlenecks
  3. datacenter-buildout-chain

And have it answer only these questions:

  • Which existing LLM / agentic AI core lines are strengthening?
  • Which subsegment is upgrading from “story” to “realization”?
  • Which name is a crowded leader rather than a new ambush setup?
  • Which small/mid-cap name has “short realization chain + direct evidence + larger repricing room”?
  • Which power/buildout provider has become an indispensable node in current AI data-center expansion?

Wiki and tracker feedback loop

1. Wiki is tracker knowledge base

Tracker should read from wiki:

  • scheme ontology
  • core / conditional / edge classification
  • current bull case / risk framing
  • comparison-page method discipline
  • the relation among cloud / production / OS / semis / power/buildout in the current scope

2. Tracker should write back to wiki

When tracker produces reusable findings, it should write back at least:

  • major scheme-level synthesis
  • reusable postmortems
  • why a new ambush candidate should be included
  • why a crowded leader / false friend should not be upgraded
  • why a power/buildout name should move from “story” to “real deployment chain”

3. Write-back thresholds still apply

Not every alert should become a wiki entry. Only findings that materially change our understanding of the current three schemes are worth recording.

Current research boundaries

In this stage, explicitly postpone:

  • Financial Institutions and Capital Markets
  • Fintech and Consumer Credit
  • Pharma and Biotechnology
  • Any cross-industry expansion before the current agentic-AI pipeline is working well
